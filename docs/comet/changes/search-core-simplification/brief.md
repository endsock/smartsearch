# 目标

以 GitHub main 916743469d8abf8d6eae300170d2bfd61fae4949 为统一基线，保留独立 CLI 的网页配置入口，将搜索核心收敛为普通单轮检索和深入多渠道研究。复用现有 Jev 客户端、渠道适配器、执行和证据结构，移除旧 embedding/classifier 远程路由与重复的主模型前置编排。

# 范围

- 普通 search：一次逻辑 Jev 选路、一个适合渠道的单轮检索。Context7 等渠道的必要依赖调用继续；成功后直接返回结果，不自动评估、补搜、过滤或汇总。渠道失败时允许已有同能力兜底，显式 fallback off 关闭兜底。
- research：复用现有多渠道并发、子问题/缺口候选、正文读取、证据评估、有限继续和可选汇总。离线 deep 保持离线建议计划；在线实际执行以同一执行器的记录为准，不再维护旧线性 research 流程。
- 新默认 Jev 优先；无 Jev 时本地直接检索。旧 hybrid 映射新默认，rules/off 映射不调用远程模型的本地方式。旧配置及 Key 保留在原文件，不再执行旧 embedding/classifier；校准入口明确退役。
- 同步 CLI/setup、网页配置及 Windows/macOS 共享配置语义、双语说明、两份分发 Skill、相应测试。保留当前 main 的 App/独立 CLI 分发、环境准备与 Skills 维护合同。

# 约束与不变量

- 当前唯一实施目录为 smartsearch-search-core-simplification，分支 codex/search-core-simplification，目标 main。
- 当前 main 的 CLI 网页入口、冻结平台包资源、App/CLI 协议和环境引导完整保留。
- 仅允许配置且启用的渠道；禁用、显式 provider 限制、cooldown、explicit-only 和能力边界不可被 Jev 输出绕过。
- 普通搜索单轮不等于一条 HTTP 请求；必要的渠道依赖、原有受限重试和同能力故障兜底保留并记录。
- 原文件中的旧 Key 不自动删除或改写；普通检索成功不冒充事实核验成功。

# 决策

- 用户在本轮明确授权：先核实、统一最新 main 和 CLI 网页入口，确认无误后开始架构精简。基线核对和 100 项网页相关测试已完成，按这一授权推进实现，不重复要求相同授权。
- 单个 Native change 由主线程实施；UI/配置消费者等独立事实调查用只读代理，最终使用独立 Verifier。不拆 Supervisor，因为各入口共用同一搜索、配置和证据合同。
- 已配置 Jev 使用语义选路；本地模式与无 Jev 兜底只做现有能力约束和简单规则，不引入替代远程分类器。
- 普通模式默认不汇总；深入模式复用现有可选汇总。开放式查询生成留给调用方 AI，Jev 只选择代码提供的候选。
- validation 参数继续接受；普通模式不因其升级为深研，strict 保留来源门槛并明确未做充分性/事实评估。深入研究保留实际读正文才能引用的合同。
- 旧 deep 是预览/手动编排工具，不作为第三种联网搜索模式；实际执行记录来源于统一执行器。
- 用户于 2026-09-23 明确指定以 ccrui 已提交并深度回测的 macOS 实现为基准继续集成。已核实其 GitHub 账号为 cr-zhichen（zgccrui）；PR #51 的 92224fbc8dc1ee832694593b2eb442971ca833b1 有 7 项 CI 通过及原生界面、arm64 App/DMG 测试记录，合并点 65e736501330adf64f5be506c0e7a10dca0462d8 已包含在当前基线中。
- 后续已合并的 ccrui PR #61（bff1caae2f4391683d90132e5fea4064593beb8a，合并点 2379557ec3e14a81c977275d8a54b86c0a10bc3e）保留为本版 App/CLI 基础。当前核查其 15 项 CI 均通过，含 macOS arm64/x86_64、通用 DMG 与原生 Intel 验证。继承这些测试的原有范围，不将本机缺 Mac 解释为工程师基准未测试；PR 自述未重做的 GUI 项也不补写为已完成。

- 第一性原理复核以“有效检索和证据”为核心：删除确无生产消费者的代码和重复步骤，保留直接工具、兼容字段、时限/取消、渠道限制与证据真实性。不引入新框架，不借此重做原生 UI 或自动合入未合并的其他 PR。
