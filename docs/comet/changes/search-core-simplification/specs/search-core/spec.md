# 两种搜索模式与统一渠道执行

## 统一基线

实现从 GitHub main 916743469d8abf8d6eae300170d2bfd61fae4949 开始，保留最新独立 CLI、网页配置、桌面协议、环境准备和 Skills 维护。原工作区及其他候选不被覆盖或清理。

### Scenario: 最新 main 与 CLI 网页能力保留
WHEN 检查实施基线与交付树，THEN 实施分支包含已核对的 main，src/smart_search/assets/ui/index.html、ui_server、smart-search ui 入口及打包资源存在；已提交的上游能力保留，原 dirty 工作区保持原样。

## 普通搜索

search 在 Jev 可用时只做一次逻辑渠道选择，选择一个适合且允许的渠道执行。Context7 按服务端排序取候选列表第一项，再读真实文档；普通请求不会追加 Jev 选库。查询成功后立即返回结果及来源，不调用充分性评估、自动补搜、过滤、汇总判断或汇总模型。选中主模型作为搜索渠道时，它的检索调用仍合法。故障兜底及模型/传输层受限重试必须遵守同一能力和总时限。

### Scenario: 普通单轮没有隐藏研究步骤
WHEN 普通 search 使用默认、旧 hybrid 或显式 validation/extra-sources/研究配置，THEN 正常成功路径恰有一次 Jev 逻辑选路及一个渠道的单轮检索；无 embedding/classifier、Jev 选库、充分性评估、过滤、自动补搜或汇总。extra-sources 仅限制本轮结果数量。必要渠道依赖和失败兜底如实记录。

## 本地与兼容路由

默认策略是 Jev 优先，本地方式可显式选择。旧 hybrid 按新默认执行，旧 rules/off 均保留无远程路由语义。旧 embedding/classifier 字段和 Key 原文件保持，但不参与任何搜索、研究、预览、诊断或校准的远程请求。Jev 缺失、失败、超时、无合适选择时，fallback auto 使用本地能力约束；fallback off 明确失败。显式本地方式无论是否存在 TypeSafe Key 都不调用 Jev。

### Scenario: 无 Jev 与旧配置不会启用另一条远程判断链
WHEN 新配置、旧 hybrid/rules/off、残留旧模型字段、缺失/失败/超时 Jev 或 fallback off 输入进入系统，THEN 行为符合上述映射，禁用远程路由得到尊重，无旧模型 HTTP 请求，用户配置与 Key 不被自动删除或改写，降级原因可见。

## 深入搜索与决策边界

research 在统一执行器中使用原问题、计划子问题、有限缺口查询、已发现 URL、现有证据和操作历史建立候选。Jev 批量选择互补动作，同轮并发；依据实际读到的证据判断缺口并继续或停止。Jev 不生成自由文本工具名、参数或查询。原 quick/standard/deep 和用户上限控制轮数、渠道数、结果数及总时间；重复动作不执行，无新证据、没有候选、证据足够或预算耗尽时停止。允许的可选过滤/汇总只属于深入模式。

### Scenario: 深研按证据缺口组合动作并受控停止
WHEN 需要多来源或首轮证据不足，THEN 可并发多个互补渠道，按缺口换引擎/候选查询/读取正文，充分时提前停止；同 provider/操作/query/URL 不重复，预算和无新证据停止有效，保留实际执行记录，离线建议步骤不冒充已执行。

## 渠道边界

所有入口共用已配置、启用、用户允许的渠道集合；保留能力分类、provider 偏好、cooldown 和 explicit-only。模型响应只匹配已发送的合法候选，检索文本作为数据，概率必须有效。直接 Exa、Context7、fetch 等命令继续按明确能力执行，不增加路由模型。

### Scenario: 模型与兜底不能突破允许渠道
WHEN 渠道缺凭据、禁用、被筛选排除、cooldown、仅允许显式调用，或 Jev 返回未知 ID/无效概率，THEN 不发出越界调用；失败保留其他渠道结果；同能力故障兜底不跨越这些限制。

## 时间预算

普通搜索默认总上限继续为 300 秒；原配置/显式 CLI timeout 覆盖保留。Jev 请求及 provider 共享剩余 deadline，期限用尽后不启动新工作；超时取消未完成请求并保留已完成证据。深入模式保留既有预算规则。检索模型的配置、显式模型覆盖和允许的故障兜底不被架构收敛意外绕过。

### Scenario: 同一时限内取消与保留部分结果
WHEN 存在慢 Jev、慢渠道、模型失败/重试、部分成功、取消或显式 timeout，THEN 使用真实剩余时限，普通默认仍 300 秒，终止及时、无期限后的新调用、已完成结果不丢失，尝试与停止原因真实。

## 证据与输出

保留 content/sources/attempts/路由与时间字段。普通检索成功只代表拿到结果，充分性标为未评估；strict 要求来源证据，不能将模型答案或空标题引用当作事实证明。research 只有 fetched/read 内容进入 citations；摘要、未读候选和模型答案不能伪装已读。评估、过滤或汇总失败保留可用结果和明确缺口。

### Scenario: 检索成功不伪装研究或事实核验成功
WHEN 只有摘要、模型答案、库候选、部分正文或判断失败，THEN 区分检索状态、充分性与来源状态，普通模式不输出已充分核验结论，深研引用必须对应实际读取内容，缺口和部分状态可见。

## 网页与原生配置入口

CLI 的本地 HTML 网页配置入口继续工作并随包分发。网页及 Windows/macOS 使用共享配置元数据；普通路由界面只提供 Jev 与本地方式，旧向量/分类输入及校准推荐退出常规流程。深研轮数、并发、过滤和汇总明确只影响 research。保留双语、Key 脱敏、草稿、原子保存、环境变量只读和本地会话保护。

原生界面以用户指定的 ccrui 已合并基准为基础：PR #51 的原生界面/打包证据，以及 PR #61 的 App/独立 CLI 结构与后续已合并修正均保留。搜索模式适配只改必要的路由显示、字段及共享文案，不另写草稿、保存、IPC、安装或更新机制。

### Scenario: 三种配置界面使用同一搜索合同
WHEN 核对 CLI 网页及基于 ccrui 已验证基准的两个原生端，THEN 显示有效的新路由方式及明确的深研参数，旧远程模型控件不再出现；保存继续走原有草稿/Key/原子保存/会话保护链，原生 CLI 环境管理不被重写。网页交互、共享 metadata/协议回归及原生增量源码核对提供本轮证据，继承基准测试与新平台实机测试分别标记。

## CLI、离线计划与指南

search 与 research 是两种联网模式。deep 继续离线生成建议计划，route 默认本地预览，仅显式 remote 可做 Jev 判断。直接工具不隐藏追加选路。旧路由参数被明确映射，route-calibrate 以不联网的退役说明返回；旧 Key 不被打印。CLI help/setup、双语手册、公开与打包 Skill 统一说明新合同。

### Scenario: CLI 与两份 Skill 无旧慢链路引导
WHEN 从 CLI/setup/help/agent-guide 或直接工具使用搜索，THEN 新旧配置映射和普通/深入边界一致，deep/route 默认保持离线，已退役校准不发网络请求，两份 Skill 一致且没有把旧路由作为正常操作的指导。
